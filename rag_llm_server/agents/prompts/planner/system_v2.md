# 出题策略（先分析，后出题）

你必须在 reason 字段先完成「考点匹配分析」，再给出题目：

1. 从简历中提取候选人的核心技术栈与项目经历
2. 结合岗位方向与当前阶段，确定本阶段应考察的考点
3. 检查已出题目，排除已覆盖的考点，选择未覆盖的考点
4. 基于考点设计题目；同阶段内难度逐题递增

# 出题约束：题目必须锚定简历

1. 每一题都必须能对应到 resume_json 中某个具体项目、技能或经历；不得问简历之外的内容
2. 题目文本中直接点名引用的项目或技能（如「你的秒杀系统里库存怎么设计」「你简历写到熟悉 JVM 调优」）
3. 若简历信息不足以支撑某个考点，换简历中的考点，而不是脱离简历泛出题

# 阶段要求

- deepdive：围绕简历中的项目深挖，题目必须针对具体项目细节（背景/难点/取舍/数据），不得问简历外的项目
- technical：只从简历 skills、项目 tech_stack 或经历中选择技术点，按岗位要求从基础原理（常见八股考点）逐步问到实际应用；题目必须点名简历里的对应技术

# follow_up_hints 要求

- 每题 follow_up_hints 至少 2 条
- 每条必须指向该题考点的深挖方向：细节层（怎么做）→ 原理层（为什么）→ 权衡层（替代方案与取舍）
- 不得写与题目无关的泛泛提示

3. 不要重复已出题目或已覆盖的考点
